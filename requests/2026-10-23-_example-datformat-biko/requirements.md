# 要件定義: _example-datformat-biko

依頼日: 2026-10-23 / モード: 要件定義 / 依頼者確認: 未(確認後に日付を書く)

## 1. 業務要件
### 背景と課題
依頼原文は「DATFormat(開達書式)に備考欄を追加したい」のみ。背景・課題は依頼者から未聴取(未確定事項 U-1)。

### 目的と期待効果
備考情報を開達書式に記録できるようにする(詳細な目的は未確定、U-1)。

### 対象業務と利用者(役割)
- 対象: 開達書式(ItemType `h4_DATFormat`、ラベル「開達書式」)の入力・閲覧。
- 利用者の役割の範囲(誰が書き、誰が読むか)は未確定(U-3)。担当者役割の既存値(Creater / Approver / ReleaseApprover / InspEXPStaff / InspEXPApprover / Q1Staff / Q1Approver)は `knowledge/methods/c2c.md`([128])にある。

### 現行業務フロー(As-Is)  ※根拠: knowledge/itemtypes/f-1-DATFormat.md, knowledge/workflows/g-WFMap.md
- 開達書式 `h4_DATFormat` は、資料名称(name)・資料分類(h4_category)・技No.(h4_class)・No.(h4_doc_class)・イベント(h4_event)・帳票リンク/実施要領リンク・帳票説明内容(h4_doc_description, text)・帳票補足資料(image)等を持つ(f-1-DATFormat.md §1.3)。
- 備考に相当する専用プロパティは §1.3 の表に無い。近い項目として「帳票説明内容 h4_doc_description」があるが、用途が備考と同じかは不明(U-2)。
- ライフサイクルは `h4_DATFormatLC`、許可ワークフローは `h4_DATFormatWF` / `h4_DATFormatEXPWF`(f-1-DATFormat.md §1.2)。
- 画面は cui の `ItemView.Form` に Column Set でプロパティを並べて表示する(f-1-DATFormat.md §1.8)。

### あるべき姿(To-Be)
開達書式に「備考」を入力・表示できる。入力形式(自由記述/長さ上限)、必須か任意か、編集可能な状態は未確定(U-2, U-4)。

### 業務ルール
未確定(U-4)。

### 対象外
未確定(U-5)。なお、本書は実現方法(どの Method・画面をどう直すか)を決めない。

## 4. 未確定事項
- U-1: 備考を追加したい背景・目的(何を書く欄か)。
- U-2: 既存の「帳票説明内容(h4_doc_description)」で足りないのか。備考の入力形式(1行/複数行)と最大文字数。
- U-3: 備考を書く人・読む人(役割)。
- U-4: 必須か任意か。どのライフサイクル状態で編集可か(承認依頼後など)。
- U-5: 対象外とするもの(開達書式以外の DATMaster・一括承認(h4_AppWFGroupForDATFormat)・EXP 版の扱い、PDF/出力への反映)。
- U-6: 画面上の位置、一覧(検索結果列)への表示有無。
- U-7: 既存の改訂履歴・コピー・改訂(Revise)時に備考を引き継ぐか。
