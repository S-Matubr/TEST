システム全体像

マルQ = 機種別(モデルイヤー/機種/仕向け/イベント)のマルQページと、必要資料・指摘・検証結果を作成→確認→承認するための管理機能。開達書式(DATFormat)/帳票マスタ(DATMaster)/マルQマスタ(DeptMQMaster)は、それらの元となるマスタ・書式の版管理と一括承認を担う。

1. データモデル(ItemTypeと関係)

マルQ系:マルQページ(h4_MQPage)に 必要資料(h4_ReqDoc)・指摘(h4_PointOut)を紐付け。必要資料には 検証結果・根拠(h4_Test_Result)が付き、指摘は各階層から起票できる。
開達書式系:帳票マスタ/マルQマスタが開達書式を保持。開達書式は版管理(Release/InRevision)され、一括承認アイテム(h4_AppWFGroupForDATFormat)で承認対象としてまとめて承認する。
一括承認:h4_ApprovalWFGroup はポリモーフィックな承認対象(h4_ApprovalTarget)と指摘・サインオフを束ねる。

2. ライフサイクル(状態遷移)

h4_MQPageLC(マルQページ)

h4_Test_ResultLC / h4_ApprovalWFGroupLC

h4_DATFormatLC(開達書式)

h4_DATMasterLC(帳票マスタ)

実線=前進、破線=差戻し/引戻し。h4_MQPage ReqDocsNLC(必要資料)は MQPage の5ステートに「やるやら変更承認(YryrRequestApproval)」「未承認(Unapproved)」を加えた7ステート。遷移は全て Aras PLM ロールで実行。遷移時の Pre/Post Method(例 h4_Call_Promote_*, h4_PostApprovalLCProcForDAT)で連動処理を行う。

h4_ApprovalWFMQAndReqDoc(マルQページ+必要資料の承認) ※h4_ApprovalWFGroupWF / h4_Test_ResultWF も同型(やるやら承認なし)

h4_DATFormatWF(帳票マスタ・開達書式:EXP検定以外)

h4_DATFormatEXPWF(開達書式:EXP検定)

h4_sendMail / h4_sendMail_DAT担当割当・承認完了・公開時のメール通知

h4_CheckIsLockRelatedDAT, h4_CheckLockHist公開(Release)前の関連DAT/ロック履歴チェック

4. クライアント画面(コードツリー)

画面用途サーバMethod表示対象特記事項
h4_AllEventTable全イベント横通し表h4_table_AllEvent_geth4_MQPage 等Wijmoライセンス取得関数 h0_getWijmolicense を呼出
h4_DATMasterTable開達書式マスタ表h4_table_DATMaster_geth4_DATFormat機種IDは h4_project から取得。保存済みレイアウト参照のみ(保存機能なし)
h4_DeptMQMasterTable部門マルQマスタ表h4_table_DeptMQMaster_geth4_DATFormatDATMasterTable のコピー。HTML/app.js 同一、Method名のみ差異
h4_EventSumTableイベントサマリ表h4_table_1event_geth4_ReqDoc 等機種IDは h4_model_name。レイアウト保存(add/edit)あり(h2_SumLayoutSave)
h4_Tree/ModTop機種別マルQページツリーh4_treeModGeth4_MQPage階層:モデルイヤー→機種→仕向け→イベント→マルQページ(5段)

共通:HTML + app.js(表示/操作)+ data.js(列定義・Method名)の3層構成。クライアントから直接検索する ItemType は UserMessage / Document / h4_ReqDoc / File / h2_SumLayoutSave。
